# RAMY Multi-Product Console

A mobile-first, device-local client workspace rebuilt from the supplied V11 Foundation. This is new development, not a recovered V12 file. The repository's original root finance calculator is unchanged.

## Use the workspace

Choose **Advisor** to enter the client name, then use **Gold** or **Portfolio** to add positions. Inputs and saved records have separate tabs. Results have their own screen; tools, themes, backups and profile settings live in the collapsible menu. The client name and save state remain visible.

**Meeting / Client** show only the client-facing presentation. **Internal** opens the revenue appendix. These are presentation modes, not authenticated roles. Share a Client HTML/PDF, never an editable master or JSON backup, with a client.

The primary theme is **Elite Beige**; the secondary theme is **Executive Blue**. The supplied R artwork is embedded in the application and report output. Interface/report labels are English; Arabic names and notes retain their writing direction.

## Run and build

```sh
python -m pip install Pillow==12.3.0
python ramy-console/build.py
python -m http.server 8000 --directory ramy-console/dist
```

Open `http://localhost:8000` for local development. Deploy the generated `ramy-console/dist/` folder to an authorized HTTPS host for phone installation. Do not deploy the source folder without running the build: icons are generated by the build.

The build also creates `RAMY_Standalone.html` (editable standalone app) and `RAMY_Web_App.zip` (static deployment bundle). Both are generated from the same source. No client record is embedded in those application builds. GitHub Actions stores the application build and test evidence as workflow artifacts; a successful build is not proof of production deployment.

## Calculation boundaries

Gold supports grams, kilograms and troy ounces; AED/USD prices per gram, kilogram or troy ounce; solving any two of spot, all-in price and premium; multiple batches; edit/delete; weighted average; and manually entered current valuation. New FX values and market prices are blank, not guessed. Imported rates are retained and must be reviewed.

Other product categories are holdings records, not invented pricing engines. Proposal and booked records are combined in totals. Cancelled gold batches and matured holdings are excluded consistently. Blank current values remain unvalued. Performance is a simple price/value comparison; it excludes unrecorded distributions, fees and cash flows. The inherited target-amount field is retained as reference only because V11 supplies no calculation for it.

Editing an existing gold batch uses its canonical AED-per-gram values so a later FX change does not change the original purchase economics. No market feed, trade execution, bank connection or financial recommendation is included.

## Saving and exports

Records and unfinished inputs save to IndexedDB with an explicit localStorage fallback. Success is shown only after persistence completes. A failure displays **Not saved**. Opening another record or creating a client saves the current record first. JSON and editable V11-style Master HTML imports are validated; read-only client snapshots are not importable masters.

Master HTML embeds the current record and all app dependencies. Direct same-file write is capability-dependent; otherwise a new download is requested. PDF buttons open an isolated report preview and the browser's print dialog. An export log records preparation or a print request, not proof that the user saved a PDF.

The service worker caches only the static application shell. It does not cache imported client files, query-string URLs, remote API requests or customer records.

## Tests

```sh
python -m pip install playwright==1.62.0 Pillow==12.3.0
python -m playwright install --with-deps chromium webkit firefox
node --test ramy-console/tests/*.test.js
python ramy-console/build.py
python ramy-console/tests/browser_test.py --engine chromium
python ramy-console/tests/browser_test.py --engine webkit
python ramy-console/tests/browser_test.py --engine firefox
```

The GitHub workflow runs each browser against HTTP localhost with actual storage and download handling. Its evidence includes test-result JSON, exported sample documents, responsive screenshots and Chromium-rendered PDFs. The optional `--memory` renderer is explicitly labelled and mocks persistence/download transport; it is not evidence of real storage, offline operation or physical-phone acceptance.

## Deployment and device acceptance

An authorized HTTPS hosting connection is still required for a permanent phone URL. Physical iPhone and Android acceptance must check the installed icon, operating-system keyboard, phone sharing and PDF save dialogs. Playwright WebKit is not a physical iPhone and Playwright Chromium is not a physical Android phone.

See [SECURITY.md](SECURITY.md) before using real client data. No production approval, regulatory certification, cloud sync or server authentication is implied.
